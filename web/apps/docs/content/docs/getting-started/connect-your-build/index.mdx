  A running NativeLink instance. If you don't have one, start with the [Quickstart](/getting-started/quickstart).
</Prerequisites>

NativeLink speaks the standard Remote Execution API. If your build tool
speaks the same protocol, you can point it at NativeLink without rewriting
your build files.

## Options [#options]

- [Buck2](/getting-started/connect-your-build/buck2): use Buck2's
  built-in remote execution client with NativeLink as CAS, Action Cache,
  and executor.
- [Siso](/getting-started/connect-your-build/siso): configure
  Chromium's Ninja replacement to use NativeLink through the RE API.
- [Pants](/getting-started/connect-your-build/pants): enable remote
  cache reads and writes from `pants.toml`.
- [BuildStream](/getting-started/connect-your-build/buildstream): point
  BuildStream artifact storage and remote execution at NativeLink.
- [CMake with recc](/getting-started/connect-your-build/cmake-recc):
  wrap CMake compile actions with `recc` and share compile outputs
  through NativeLink.

## Common NativeLink endpoint [#common-nativelink-endpoint]

The examples below assume a NativeLink server exposing CAS, Action Cache,
execution, capabilities, and ByteStream on port `50051` with instance name
`main`.

The BuildStream page follows the checked-in integration test, which uses
the default empty instance on the same local port.

For a local Docker server, start with
[Getting Started → Quickstart](/getting-started/quickstart). For the Buck2 integration
test shape, see

## FAQ [#faq]

<Accordions type="multiple">
  <Accordion title="Can different build tools share one cache?" id="can-different-build-tools-share-one-cache">
    Yes: they speak the same protocol against the same endpoint. Each
    tool hashes its actions differently, so tools won't share entries
    with each other, but every client of the same tool and toolchain
    will.
  </Accordion>
  <Accordion title="Why does the instance name matter so much?" id="why-does-the-instance-name-matter-so-much">
    The instance name selects which configured store or scheduler a
    request is routed to. If a client sends an instance name the server
    does not expose, NativeLink rejects the request with an error of the
    form `'instance_name' not configured for '...'`; depending on the
    client, that shows up as a cache warning or a failed build rather than
    a cache hit. Every client targeting a cache must send an instance name
    the server exposes.
    <SourceLink file="nativelink-service/src/ac_server.rs" symbol="inner_get_action_result" />
  </Accordion>
  <Accordion title="Which client is the fastest way to try NativeLink?" id="which-client-is-the-fastest-way-to-try-nativelink">
    If you're on CMake,
    [recc in cache-only mode](/getting-started/connect-your-build/cmake-recc)
    needs no worker fleet and no build-file changes. For Bazel, two
    `.bazelrc` lines against the [Quickstart](/getting-started/quickstart) server
    do it.
  </Accordion>
</Accordions>
